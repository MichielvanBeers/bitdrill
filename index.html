Cheat sheet

  
Bit n counts from the right, starting at 0. 1 << n is a number with only bit n set.


  
Reading binary


bit:    7   6   5   4   3   2   1   0
value: 128  64  32  16   8   4   2   1

1010 0110 = 128 + 32 + 4 + 2 = 166


  
Hex: one digit is exactly 4 bits


0 0000   4 0100   8 1000   C 1100
1 0001   5 0101   9 1001   D 1101
2 0010   6 0110   A 1010   E 1110
3 0011   7 0111   B 1011   F 1111

  
Anchors: 1 2 4 8 are single bits, F is all four, 0 is none, A (1010) and 5 (0101) alternate. Every other digit is a sum: B = 8+2+1, 6 = 4+2.

  
Never convert a whole hex number. Read each digit on its own: 0xA6 = 1010 0110.


  
Thinking in hex


0x0B | 0x03   →  0|0 = 0,  B|3 = 1011|0011 = 1011 = B  →  0x0B
0x3A + 0x15   →  A+5 = 15 = F, no carry;  3+1 = 4     →  0x4F
0x2C + 0x15   →  C+5 = 17 = 16+1 → 1, carry;  2+1+1 = 4 →  0x41

  
& | ^ work per digit, the nibbles never affect each other. Addition carries at 16 from the low digit into the high one.


0x0F  low nibble       0xF0  high nibble
0xFF  full byte        0x80  top bit of a byte
0x01  bottom bit       0x55 / 0xAA  alternating


  
Decimal in code

  
Decimal digits don't line up with bits. Know these on sight: powers of two (1, 2, 4 … 128, one bit) and one less than a power of two (15, 31, 63, 127, 255, all lower bits). For anything else, split into powers of two:


flags & 72   →  72 = 64 + 8  →  bits 6 and 3  →  0100 1000 = 0x48


  
The four operators


  1100      1100      1100     ~ 1100
& 1010    | 1010    ^ 1010
= 1000    = 1110    = 0110     = 0011

  
AND keeps bits (masking in). OR turns bits on. XOR flips bits / finds differences. NOT inverts all.


  
Single bit


x |  (1 << n)      set bit n
x & ~(1 << n)      clear bit n
x ^  (1 << n)      toggle bit n
(x >> n) & 1       read bit n (0 or 1)
(x & (1 << n)) != 0   is bit n set?


  
Shifts

  
x << k multiplies by 2k (bits falling off the top are lost). x >> k divides by 2k, rounding down (for unsigned values).


  
Masks and fields


((1 << w) - 1)            w ones at the bottom
((1 << w) - 1) << lo      w ones starting at bit lo
(x >> lo) & mask           read field
(x & ~(mask << lo)) | (v << lo)   write field

  
Field [hi:lo] has width w = hi − lo + 1. Writing a field is read-modify-write: clear first, then OR the new value in. This is how hardware registers get updated.


  
Flags


READ = 1 << 0, WRITE = 1 << 1, EXEC = 1 << 2
p = READ | WRITE            combine
p & WRITE                   has WRITE? (non-zero)
(p & m) == m                has ALL of m
(p & m) != 0                has ANY of m
p & ~m                      remove m
p ^ m                       toggle m


  
Classic tricks


x & (x - 1)     clear lowest set bit
x & -x          isolate lowest set bit
(x & (x-1))==0  power of two (x > 0)
x & 1           odd?
x ^ y ^ y == x  XOR undoes itself

  
-x in two's complement is ~x + 1.


  
Real-world gotchas

  
Precedence: in C, C++, Java and JS, x & m == m parses as x & (m == m). Always parenthesise: (x & m) == m.

  
Width: ~ works on the whole int (32/64 bits), so ~0x0F is not 0xF0 unless you mask with & 0xFF. In JS, bitwise ops are 32-bit signed; use >>> 0 to get unsigned.

  
Signed right shift copies the sign bit (arithmetic shift). Use unsigned types for masks.

  
Shifting by ≥ the type width is undefined behaviour in C/C++.
